# Skill Hub：52 技能中心与个人技能

## 范围与边界

保留 `/skills` 的「Skill 广场」，内部为技能中心（系统/社区）与我的技能（全部、分享给我、我的分享、我的发布）。只部署52，不涉及54、知识库改造。社区审核位于管理员工作区。

业务主体在 `app/services/skill_hub`，使用独立资源表串接原生 skill/package 版本快照；系统技能原来的发布、目录管理和权限仍保留。旧管理API增加对象级保护，不能作为查看私有草稿的后门。

## 行为约定

- 所有登录用户可创建、ZIP/文件夹导入、编辑、测试、发布自用版本。保存生成新草稿，不改正在使用的快照。
- 独立技能根目录必须包含唯一SKILL.md；多技能作为整包处理，公共文件、包内成员和依赖随整包复制。
- 分享固定版本，只读/使用；允许Fork须主动勾选。接收者确认新版，撤销/过期不收回已独立复制的副本。
- 系统Fork默认关闭，需要管理员确认许可后开放；社区安装复制为个人资源，不直接运行社区原件。
- 社区首次/更新都人工审核不可变投稿快照，禁止自审，新版审核不覆盖旧上架版本。作者/管理员可下架；安全停用与普通下架不同。
- 安装检查不通过时保留不可用草稿供配置，不将它混入聊天目录。用户确认升级；有本地修改则另建副本。
- 内部运行名唯一，展示名称允许重复。聊天按真实用户授权加载；定时任务固定原生版本，明确改绑定才升级。公共任务不能绑定个人或分享技能。
- 模拟隔离测试无真实模型/工具调用：断网、只读、低权限Docker；声明依赖须脚本覆盖模拟调用。整包支持按成员指定脚本，`skill_dependency_mocks.declared/invoke`供模拟验证。
- 「真实业务试用」进入真实聊天，只使用已发布自用版本，明确提示模型费用及工具副作用，不把草稿送入正式对话。
- 用户注销保留来源锚点，私有资源封存且不可公开。历史安全停用不随执行管理员删除而失效。

## 持久化

- 正式源码：52 Gitea main；服务源码分支 `feat/skillhub52-20261010`。
- `docker-compose.yml` 开启SKILL_HUB_ENABLED，后端 Dockerfile.skillhub52 拷入业务源码和全部迁移；前端从源码执行 tsc/Vite 构建。
- PostgreSQL独立业务表以及原有版本表存于现有postgres宿主挂载。
- 快照存于宿主持久 knowledge 下 `skill_versions` / `skill_package_versions`，不是容器可写层；临时处理目录也位于持久挂载。
- 启动执行幂等迁移和安全孤儿恢复；只回收超过24小时、无数据库引用的个人快照，不删除系统或已提交版本。
- 正式镜像记录commit SHA标签，真正Coolify部署源与实际compose同步配置，保留原有secret和runtime挂载。
