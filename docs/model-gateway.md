# 企业模型网关

模型ID用于调用与配置关联，显示名只用于界面。可用模型接口保留 `models` 和 `default`，增补 `display_names`。模型名称修改后，当前窗口立即更新，其他窗口在重新获得焦点或收到同源更新通知时刷新。

默认角色规则：`e` 开头模型允许三类角色，`ali` 开头模型允许操作员和管理员，其他前缀默认仅管理员。角色覆盖配置与个人额外授权由共享授权服务执行；停用模型不会进入任何角色的可用模型列表。用途的Chat默认值不改变网关原有非聊天模型筛选。

`/models/authorization` 提供单模型查询与更新；恢复默认仅影响该模型。`/models/users/{id}/extra-grants` 管理角色以外的模型，保存使用人员revision检测并发变化。旧 `/models/policies` 接口作为兼容适配层保留：角色名单替换对应覆盖，个人名单只保存额外授权。

输入、输出、命中缓存价格均为可空字段，单位为USD/百万Token，零代表零价格，空代表未知。隐藏的能力和价格来源字段保持原有数据。后台受限测试仍保持价格来源检查、调用额度和脱敏等安全约束。

## 数据迁移与部署

先备份数据库，再执行 `python migrate_model_gateway_v2.py` 查看差异，执行 `python migrate_model_gateway_v2.py --apply` 应用。应用启动也会幂等检查；数据库中的迁移标记确保容器重建不会重复重置角色授权。

首次迁移清除旧角色模型白名单，采用新的前缀默认规则；个人名单中超出新角色权限的模型保留为额外授权。管理员之后的手动设置不受重复迁移影响。迁移不修改账号、密码、平台角色模板或其他资源授权。

52部署需同步正式源码、构建revision、Coolify保存的Compose来源和实际生成的Compose；模型元数据与授权存储在原PostgreSQL持久卷。只重建前后端，不重建数据库。回滚旧授权语义时须使用迁移前的模型授权备份，不能只回滚镜像；避免恢复整库覆盖其他模块的新数据。

验证脚本：后端 `_test_model_gateway_v2.py`、`_test_admin_stage2_models.py`、`_test_config52_regressions.py`，浏览器 `test/_test_model_gateway52.mjs`。浏览器脚本仅接受52地址和临时测试账号，不使用真实用户密码。
