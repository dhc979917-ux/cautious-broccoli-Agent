# Skill 广场与平台技能管理边界

- Skill 广场维持「技能中心／我的技能」两模块；独立技能名称仅展示，技能包名称进入固定版本的成员卡片列表。「查看详情／预览」是独立入口。
- 平台单技能、整包的派生许可在 Skill 管理 → 操作 → 编辑保存。包成员继承整包许可，服务端拒绝成员单独设置。许可与原元数据由同一数据库会话提交，不更改原角色权限或隐藏状态语义。
- 平台资源未开放派生时，广场返回文件清单及目录结构，但文件预览与下载接口拒绝内容读取；管理员后台的版本与文件管理独立于此限制。
- 个人资源仍按所有者、固定版本分享、社区批准版本访问；个人编辑不受平台开关影响。无派生许可的分享只展示目录。社区预览读取批准版本，前端版本过期时返回冲突而不是读取新版草稿。
- 文件浏览是只读共享组件，仅展示当前目录。可点击目录、返回父目录、用面包屑定位；开放许可后可查看 Markdown 或源码，禁止 Markdown 自动加载外部链接／图片。详情与包成员来自原 UUID 的固定快照，不生成可独立派生的包内成员。
- 管理员上传区位于 Skill 管理顶部右侧，与搜索至新建按钮横向对齐；支持点击 ZIP、拖 ZIP、拖完整目录及多批目录读取。继续使用原系统上传 API、异步作业和结果提示，不混入个人导入流程。上传权限叶子和原服务端校验不变。

## 隔离验证

所有写入验收仅访问 52 的隔离 8092 服务，独立 PostgreSQL、Redis 与运行数据。`test/_fixture_skillhubui52.py` 仅允许隔离环境生成短期验收身份，身份 JSON 不纳入源码。

准备 `._qa-identities.json`后，按顺序运行：

```sh
node test/_test_skillhubui52_api.mjs
node test/_test_skillhubui52_guards.mjs
node test/_test_skillhubui52_ui.mjs
node test/_test_skillhub52_api.mjs
```

UI 脚本自动生成隔离 ZIP／目录夹具，不依赖真实用户数据。生产部署只重建前后端，保留数据库、Redis、技能根目录、知识快照和密钥挂载；同时校验运行镜像与提交 SHA、Coolify 实际配置及可重建配置。
