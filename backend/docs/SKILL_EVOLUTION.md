# 受控个人技能进化

## 功能边界

- 每位用户默认关闭；在技能广场「我的技能」或问答技能面板明确确认后开启。
- 成功问答在提交回复后异步入队；失败不影响回复。无需改进直接结束，不生成版本。
- 授权来源首次派生完整私有副本，后续更新同一副本；来源、分享固定版本和历史版本不可变。
- 没有合适技能时可以创建私有技能，禁止借创建绕过来源派生权限。
- 发布仅供本人使用，不自动分享或上架社区。仅原问答会话选中的来源成员关联新版本，不改全局选择或定时任务。
- 并存人工草稿、版本冲突、来源授权撤销或验证不足时不覆盖原发布版本。

## 验证和控制

模型只能提交有类型的 skill_manage 提案，不能通过此通道执行业务工具或任意命令。
提案须引用本次真实用户反馈或成功工具证据，并提供虚构输入和验收条件。
文件修改在独立 staging 中生成不可变候选，复用技能广场隔离测试。
业务验证是模型生成的虚构 before/after 与回归评估，**不是生产业务执行证明**；界面保留验证方式及警告。
脚本、配置、删除、入口重写等高风险变更须人工确认；验证失败最多自动修复两次。
允许关闭、按资源暂停、拒绝候选、处理冲突后重试，以及使用既有版本管理回滚。
上下文与候选限量并脱敏；私有令牌、邮箱、绝对路径与注入型内容拒绝写入。

## 持久化与扩展

四张独立表通过 migrate_skill_evolution_v1.py 幂等添加，不修改旧业务表结构。
作业按已完成消息幂等；数据库队列及版本目录使用现有持久卷。
PostgreSQL session advisory lock 串行化后台恢复和处理，多副本不会重置正在运行的作业。
故障释放连接后，新 worker 使用已有不可变候选重新验证，不重复派生；SQLite 仅支持单进程开发。
policy/provider/lifecycle/runtime/worker 分层，模型网关和验证 adapter 可替换。

## 配置

- SKILL_EVOLUTION_ENABLED=true：服务总开关；不代表替用户开启。
- SKILL_EVOLUTION_WORKER_ENABLED=true：后台 worker 开关。
- SKILL_EVOLUTION_MAX_JOBS_PER_DAY=20：每用户滚动 24 小时额度。
- 所有用户 enabled 默认 false；停用不移除历史版本或原发布版本。

## 52 隔离验证

测试脚本含 QA 数据库及隔离环境 guard，禁止在正式库制造测试用户或数据。
backend/_test_skill_evolution52.py、_edges.py、_worker.py：编排、安全、恢复、包与并发。
backend/_test_skill_evolution52_live.py、_chat.py：真实模型网关与 REST 问答入队。
test/_test_skill_evolution52.mjs：桌面/移动端设置、变更与会话关联。
已有技能广场边界、运行时与固定任务版本回归必须同时通过。
